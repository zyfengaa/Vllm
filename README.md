## 这份文档解决什么问题

- **只背参数不懂约束**：`--gpu-memory-utilization`、`max_num_batched_tokens`、`block_size` 背后是一组守恒关系，不理解就只能碰运气。
- **用旧版本的直觉答新版本的问题**：vLLM 三年发了 102 个版本，经历过 V0→V1（2025）、Model Runner V1→V2（2026）两次重写，并在 0.25.0 删除了 PagedAttention 原始实现。
- **网上资料只讲"是什么"，不讲"为什么改、什么时候会坏"**：本文把每次架构变化都还原成一次具体的权衡（显存换带宽、算力换带宽、复杂度换性能）。

## 先看这张表：五条技术主线

所有版本变化都可以归到这五条线上，每条线都有自己的目标与代价：

| 主线 | 目标 | 关键手段 | 代价 / 边界 |
|---|---|---|---|
| ① KV 显存管理 | 单位显存装更多 token | 分页 → 前缀缓存 → 低精度 KV（FP8/NVFP4/2bit）→ 分层 offload → 可扩展 KV | 精度、查找开销、PCIe 带宽 |
| ② 调度与并发 | 让 GPU 永不空转 | continuous batching → chunked prefill → 多步调度 → 异步调度 | 延迟抖动、实现复杂度 |
| ③ 执行与编译 | 降低每 step 的 CPU/launch 开销 | CUDA Graph → piecewise/full → torch.compile → MRv2 → IR | 动态形状、捕获失败、编译时间 |
| ④ 并行与通信 | 单卡放不下、单机不够快 | TP → PP → DP → EP(+EPLB) → CP/DCP/PCP | 通信墙、负载不均、拓扑约束 |
| ⑤ 服务化与生态 | 从库到平台 | OpenAI API → 指标 → 结构化输出 → gRPC/Rust 前端 → PD 分离 | 协议兼容、运维复杂度 |
